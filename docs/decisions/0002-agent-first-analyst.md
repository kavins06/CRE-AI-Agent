# ADR-0002: Build and measure the analyst before expanding infrastructure

## Status

Accepted by the owner in the coordinator conversation:
https://app.devin.ai/sessions/492866a8c1be4f4caee4c55096f31e28

## Decision

The next release prioritizes an operational multifamily acquisitions analyst:
its character, investigation, knowledge use, skills, recommendations, independent
criticism, questions and revisions. Deterministic finance, Excel, state and gates
remain instruments and enforcement boundaries, not substitutes for judgment.

Use one accountable lead, bounded document extraction and research roles, and an
independent advisory reviewer. Underwriting and diligence are reusable skills;
additional agents need demonstrated benefit rather than another fixed role name.

The owner authorizes normal Devin sessions and quota for CRE analyst execution,
replacing the previous ChatGPT-only/OpenAI-only restriction for those runs.
Development and execution remain on the owner's Outpost. No new separately billed
model API, shared-host runtime changes or access to private evaluations is approved.

## Sequence

1. Replace placeholder role prompts and skills with a complete analyst charter,
   investigation method, role contracts and evidence-aware procedures.
2. Curate legally usable references and connect the existing knowledge provider to
   canonical analyst tools. Keep public reference, firm policy, user preference,
   deal evidence and evaluator truth separate.
3. Implement the smallest scoped Devin runtime needed to exercise the brain.
   Verify actual provider controls rather than relabeling synthetic capabilities.
4. Exercise document evidence, tool-backed underwriting, independent objections,
   material questions and response-to-correction on permitted public development
   cases. Diagnose failures and refine the brain.
5. Expand deliverables and quality coverage before commercial onboarding,
   broad connectors or automated learning infrastructure.

This supersedes ADR-0001's requirement to stop brain work until Codex runtime proof.
It does not supersede its execution, tenant, provenance or publication safeguards.

## Release evidence

A first analyst demonstration must show genuine model execution using a recorded
brain release, investigation choices, cited evidence, deterministic calculations,
review objections and revisions. Unit tests, prompt completeness and FakeRunner
replay are not analyst-quality evidence.

The lead must distinguish seller assertions, verified facts, assumptions, conflicts
and interpretation; unknowns are never silently zero-filled. Authoritative deal
quantities resolve through existing state and calculation tools. References never
become property facts solely because they were retrieved.

Production publication remains gated. A provider lacking a required capability
must refuse that production path, not claim compliance or fabricate accounting.
Draft research/probe evidence must be explicitly distinguished from accepted
deliverables. Do not weaken tests, task criteria, owner guards or private-eval
isolation. Existing task flags require their original same-session verification.

## Coordination

Research informs both knowledge integration and brain authoring. Runtime integration
can proceed independently. An integration stage combines those outputs and adds
public behavior checks; a separate source review then challenges the result.
Use separate Outpost checkouts and non-overlapping ownership. Never start rootful
Docker or expose build credentials, repositories or evaluator truth to the analyst.

## Definition of done

Working code and usable knowledge/skills, successful deterministic checks, genuine
analyst behavior evidence, resolved blocking review findings, and an honest report
of any limitations. Missing scoped API access or an unsupported provider guarantee
is a blocker to live completion, not permission to label the agent finished.
